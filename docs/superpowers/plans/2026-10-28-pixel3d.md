# pixel3d Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build pixel3d: a pixel-art → 3D-print web app plus a headless CLI / HTTP / MCP batch API, all sharing one engine.

**Architecture:**
- `packages/core` is a pure TypeScript engine with no DOM: bytes → pixel grid → palette → heights → manifold-3d meshes → STL/3MF bytes.
- `packages/web` (Svelte 5 + Vite + Three.js) and `packages/cli` (Node) only call core.
- `convert(bytes, preset)` is the single entry point for every headless path, so UI and batch output are identical.

**Tech Stack:** TypeScript 5, npm workspaces, Vitest, manifold-3d (WASM), fflate (zip), upng-js / jpeg-js / omggif / @jsquash/webp (decoders), zod (preset schema), Svelte 5, Vite, Three.js, hono + @hono/node-server, @modelcontextprotocol/sdk.

**Spec:** `docs/superpowers/specs/2026-10-27-pixel3d-design.md`.
**UI reference:** `docs/mockups/app-mockup.html` (v0.1.9). The web tasks port its layout, copy and behavior, and the mockup's `traceLoops`, `floodClear`, `kmeans`, `detectScale` and `pieces` show working versions of those algorithms.

## Global Constraints

- **Version:** a single source in the root `package.json`, starting at **0.2.0** (the mockup used 0.1.x). Bump the patch on every task commit.
  - Commit subjects start with the version, e.g. `v0.2.3: palette reduction`.
  - Show it in the web footer and in `px3d --version`.
- **Units:** mm everywhere in core. Inches are a UI display option only.
- **Output quality:** every exported mesh is manifold, checked with manifold-3d in tests. Color parts sit flush on the base with no gap.
- **Pixel art cap:** 512 px on the longest side. Bigger or non-pixel-art images are pixelated, never refused.
- **Pixelate:** default 32 px across (range 8–128) and 8 colors (range 2–16), using seeded k-means. The background tolerance is 40 RGB when pixelating.
- **Background:** on by default, tolerance 10 % (range 0–50 %) of the full RGB distance (441.7). Flood fill runs from the image edge only.
- **Heights:** 0.2–20 mm per color.
- **Undo:** 50 steps.
- **Keychain:**
  - Hole: Round or Square, 2–10 mm.
  - Loop: angle 0–359° (0° is up, clockwise); thickness equals the base thickness, or the lowest color height when there is no base.
- **Wall:** 0.8–5 mm.
- **Magnets:** sizes 8×3, 6×2, 10×3 mm, plus custom.
- **HTTP:** port 7300, bound to localhost.
- **3MF:** Bambu Studio is the target that must work. Orca and Prusa are checked by metadata-structure tests only.
- **Copy:** UI text is taken from the mockup verbatim: sentence case, no all-caps labels.
- **Git:**
  - Work on branch `build/app`. At the end, merge using the NAS recipe in `Z:\Git\CLAUDE.md` (`git branch -f master build/app; git switch master; git push`), then delete the branch.
  - Never commit `node_modules/`, `dist/` or screenshots.
  - Tick each task's checkboxes in the same commit as the task.
- **Do not create the public GitHub repo or push** without asking the user first.

## Review Focus

1. **Degenerate images:** a 1×1 image, a fully transparent image, a single-color image, and an image that is empty after background removal. Each must give a clear error in the report and UI, never a crash or an empty 3MF. *(Task 8 test.)*
2. **Booleans that split the model:** a hole that cuts the art in two, or a magnet overlapping the hole. The output must stay manifold, and the piece count and warning must update. *(Task 6 test.)*
3. **Bad preset input:** invalid JSON, an unknown field, a newer `version`, or a color rule matching nothing. Each gives a readable error naming the field. In batch, the run continues with the other images. *(Tasks 4 and 9 tests.)*
4. **Non-square pixels with halves and rotation:** "Keep aspect ratio" off, Two halves, rotated 90° about Z. The mirrored back must still overlay the front exactly. *(Task 5 test.)*
5. **Large pixel art at the cap:** a 512×512 sprite with 16 colors must convert in under 5 s in Node and must not freeze the UI. Mesh building moves to a worker if needed. *(Task 8 test, Task 14 check.)*
